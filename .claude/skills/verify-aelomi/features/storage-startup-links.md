# Storage startup and URL links

Aelomi opens pages only after its data folder is ready. A refused cloud folder shows its resolved path, explains database corruption, and gives steps to move it back to this Mac. Clicking a URL in a page opens the default browser while the Aelomi page stays open.

## Sub-features

- `cloud-refusal` shows where the data really is and says cloud sync corrupts the database. Aelomi hasn't changed anything in the data folder. The title receives focus.
- `cloud-leaf-link` keeps Aelomi open while Finder steps open the link's parent, remove only the link, open a second Finder window with File > New Finder Window (⌘N), open the cloud folder's parent there, uncover the window from step 1, and drop the data folder onto an empty area of it, away from other folders. A Go to Folder check opens the exact configured path and requires the workspace files directly inside the configured parent before restart. A different folder name gets an explicit rename. Quit and reopen comes last.
- `cloud-shared-link` names the link into cloud storage, says Aelomi cannot keep its database there and changed nothing, and requires a regular folder on this Mac. It warns that turning off syncing can remove local files, including other apps' files. It gives no removal or movement instruction. Restart is a separate last step.
- `cloud-override` tells the user to set `AELOMI_DATA_DIR` outside cloud storage or unset it, then reopen.
- `cloud-path-copy` selects a complete path chip with one click or keyboard focus for copying with ⌘C. Native accessibility focus can require ⌘A first.
- `pending-refusal` blocks a new workspace after an incomplete cloud move, remembers the last-seen folder, and offers a confirmed empty-workspace choice.
- `storage-refusals` shows specific messages for a locked folder, a newer or unknown format, and a read error.

- `url-browser` opens http, https, and mailto links in their default application.
- `navigation-guard` keeps the window on the app when another origin tries to navigate it.

## How to get to it (user POV)

- Launch Aelomi with its data folder inside cloud storage.
- Relaunch after a cloud refusal with the configured destination missing or lacking stored workspace-root history.
- Launch a second Aelomi process on the same folder to see the locked message.

- Click a URL link in the page body.

## Driving it with app.sh and mock-drive

Preconditions:

- Use synthetic folders and a dev build. Read the launch instructions in `../SKILL.md`.
- Create a fake cloud folder outside the checkout. Set `AELOMI_CLOUD_ROOTS` to it for each dev launch. Use an absolute canonical path. Never use the real cloud folders.
- For the equal-name leaf case, create a sibling link named `Aelomi` to `<fake cloud>/Aelomi`. Also try different names with `<fake cloud>/Aelomi Notes`. Set `AELOMI_DATA_DIR` to the link. Also try a trailing slash and `missing/../Aelomi`.
- For the shared case, create a synthetic `Library/Application Support` link to the fake cloud folder and configure `<link>/Aelomi Dev`. For the override case, configure `<fake cloud>/Aelomi Dev` directly.

- **Leaf refusal.** Run `$S/app.sh doctor "$RUN"`, then `$S/app.sh tree "$RUN"`. Expect `Move your data folder out of cloud storage`, both parent-path chips, and a configured-path chip. Every Go to Folder instruction says to press Return. The check requires `format.json` and `docs` directly inside the configured parent before restart. Its split remedy opens the destination from its own chip before the folder is copied in the other window. It names Move Item Here while Option is held and each Return-based rename. No remedy depends on Undo Move.
- **Pending refusal.** Use one synthetic `AELOMI_RECOVERY_DIR` directory outside the workspace and fake cloud root for every launch in this scenario. Seed the cloud folder with a known page. Launch through a leaf link and expect `CloudPath` in the log and a record with the configured path, cloud path, variant, and timestamp. Quit and clean up the owned run. Remove only the synthetic link with `rm`, then use `mv` to misplace the cloud folder under another destination subfolder. Save the parent listing. Relaunch with the same overrides. Expect `Finish moving your pages`, the last-seen path, Show in Finder, and no link-removal step. Compare the listing exactly. The configured path must remain absent.
- **Partial move.** Put `format.json` and an empty `docs/` at the configured path. Relaunch and expect Finish moving your pages. Compare the destination and record bytes exactly. A moved folder with a broken marker, or `docs/` without a marker, reports unknown format even with a pending record. Compare all destination and record bytes exactly.
- **Unreadable record.** Corrupt this configured path's hashed JSON file. With the configured path missing, relaunch and expect Aelomi lost track of where your pages were. Expect the labeled "Aelomi expects your pages at:" chip, the exact-path check, and restart. Confirming a new empty workspace still works. Compare the original folder bytes exactly.
- **Correct move.** Show in Finder reveals the last-seen folder in its parent. If that path moved, expect an inline error and locate the folder manually. When Finder interaction is prohibited, leave the button unpressed and record this proof limit. Use `mv` on the synthetic folder to put it at the exact configured path, including its expected name. Check `format.json` and `docs` there before restart. Relaunch with the same overrides. Expect the exact original Page body text and no recovery record. Compare original workspace bytes before reopening.
- **Explicit new workspace.** Repeat the refusal and missing-destination setup with a fresh synthetic workspace and recovery directory. Capture the original folder's file hashes. Press `$S/app.sh press "$RUN" "Start a new empty workspace here"`. Expect the alert dialog `Start a new empty workspace?` and the warning that pages stay where they are. Keep moving my pages has initial focus. Press it and expect the finish-moving screen and no new folder. Open the dialog again and press Create empty workspace. The dialog visibly labels the new destination and last-seen path. Expect an empty workspace and a cleared record. Quit and relaunch on the same synthetic folder. Expect it to stay empty without a Getting started page. A `.DS_Store`-only destination accepts explicit creation and preserves that file. A destination with real items keeps Finish moving, and the confirmation names those items. Also put items at an initially absent destination while confirmation is open. After the refusal, Keep moving my pages must show the rename step. After failed creation, Keep moving my pages shows refreshed steps for the folder now present. A failed marker publication that leaves `format.json.tmp` permits a successful retry. An existing destination shows a rename step with its own configured-path and parent-path chips. The step opens a new Finder window, checks the exact configured path first, and says that it is not the folder Show in Finder selected. It then renames the existing destination to "<name> (old)" before moving pages. The not-empty message says the listed items may be pages and points to this step. No rename removes data. Compare every original cloud-folder byte and its listing exactly. Capture the screen and confirmation in the Mac's current appearance.
- **Shared refusal.** Expect `This folder is a link into cloud storage:` on the synthetic `Application Support` chip and `Aelomi can't keep its database there and hasn't changed anything.` The next step requires a regular folder on this Mac and warns that turning off syncing can remove local files, including other apps' files. No step tells the user to change sync settings, trash, move, or replace anything.
- **Quit refusal.** Quit the refused native app with ⌘Q. Expect immediate exit without a dialog. The shell log has `quit flush via=ExitRequested pending=None`, `quit frontend ready skipped: storage refused`, and no `quit draining` line. The separate SHELL-9/SHELL-10 acceptance case proves the ready-workspace positive control. A drain timeout there still asks, **Keep app open** returns to the page, and a second timeout followed by **Quit anyway** exits with exactly one confirmation call.
- **Refused commands.** In Acceptance 7, press ⌘K and activate `openPalette` through `__aelomiMock.menu.activate`. Expect no palette, no dialog, no editor, and zero `docLoad` calls. A cancelable ⌘K keydown dispatched on `window` returns `true` on the refusal and `false` in the ready-workspace positive control.
- **Override refusal.** Expect only the override and restart steps, with no Finder movement instructions.
- **Copy a path.** Click a parent-path chip, press ⌘C, and compare the clipboard with the exact displayed path. Focus another chip by keyboard and repeat. The whole path is selected, including spaces and non-Latin characters. `app.sh focus` sets native accessibility focus; if it does not establish text selection, use ⌘A then ⌘C and report that separately from automatic selection.
- **Appearance, real app.** Follow the [appearance rules](../SKILL.md#rules). A refused workspace has no Settings or theme command. Capture each variant in the current appearance and name that appearance in the evidence. Run the read-only mapping `APPEARANCE=$([ "$(defaults read -g AppleInterfaceStyle 2>/dev/null)" = Dark ] && echo dark || echo light)`. Confirm it against the first screenshot before using the label. See [Gotchas](../SKILL.md#gotchas) for the preference's output. For the leaf variant, run `$S/app.sh screenshot "$RUN" "cloud-leaf-$APPEARANCE"`. Use `cloud-shared-$APPEARANCE` and `cloud-override-$APPEARANCE` for the other runs. Each shot must show the complete path, readable instructions, and `Keep Aelomi open until the last step.`
- **Appearance, both themes.** After cleaning up the dev run, write a separate mock flow for `mock-drive.mjs --flow`. Before navigation, seed `__aelomiMockSetup.storageStatus` with each variant's `CloudPath`, as in `tests/playwright/storage-refusal.spec.ts`. Cover `LinkAtDataFolder`, `SharedLink`, and `Override`. See `CloudRecovery` in `src/ipc/bindings.ts` for all three recovery shapes. For each variant, call `page.emulateMedia({ colorScheme: "light" })` and `page.emulateMedia({ colorScheme: "dark" })` before its captures. Use `shot("mock-cloud-leaf-light")`, `shot("mock-cloud-leaf-dark")`, `shot("mock-cloud-shared-light")`, `shot("mock-cloud-shared-dark")`, `shot("mock-cloud-override-light")`, and `shot("mock-cloud-override-dark")`. Check the same paths and instructions. Label these as mock evidence.
- **URL link.** Launch on a synthetic folder with one page and a URL link to `https://example.com`. Run `$S/app.sh tree "$RUN"` to find its link label. Capture `url-before`, press the link with `$S/app.sh press "$RUN" "Example"`, and capture `url-after`. Expect `url opener launched=true` in the shell log. This log proves the OS opener launched, not browser receipt. Observe the browser and confirm Aelomi still shows the same page.
- **Pointer.** Click the link with native pointer input and expect exactly one new `url opener launched=true` line.
- **Modified click.** Hold Shift while clicking the link and expect no new opener line. Repeat with Option, Control, and Command when available.
- **Selection.** Double-click the link with native pointer input. Expect only one new opener line. Then make a later single click on the selected link and expect one more opener line, exactly two for that sequence. Drag-select its text and expect no new opener line.
- **Context menu.** In a packaged build, right-click a link targeting a synthetic loopback request counter. Expect no WebKit link menu and no request at the counter. `allowLinkPreview` must be false in the bundle configuration. Capture the app and the request count.
- **Navigation guard.** In the dev window’s Web Inspector console, assign a synthetic loopback URL to `location.href`. Expect `url navigation refused=true`, no request at the loopback server, and the original page still visible. This action must bypass the captured link handler.
- **Quit survival.** Type a unique synthetic marker, quit with ⌘Q, relaunch with the same isolated data folder, and confirm the exact marker in the editor.
- **Mock URL link.** Run `pnpm test:e2e e2e/url-links.e2e.ts`. Expect the open-URL call to receive exactly `https://example.com`, and the page heading and body to remain.
- **Cleanup.** Run `$S/app.sh cleanup "$RUN"`. Keep the named evidence directory.

## Gotchas

- `AELOMI_CLOUD_ROOTS` applies only in debug builds. Never move or modify the real data folder for this check.
- AXPress produces a zero-detail click. Prove it separately from pointer input.
- A refused startup still has an accessible IPC status for the launch helper. No editor is mounted.
