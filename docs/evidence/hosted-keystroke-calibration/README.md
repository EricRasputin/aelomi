# Hosted keystroke gate calibration

This record calibrates hosted regression gates. It makes no app speedup, local SPEC pass, native presentation, or causal CPU claim. The orchestrator must countersign the proposed hosted ceilings. This record does not claim that countersign.

## Environment and data shape

The collector reads every `CI` workflow run created from `2026-10-13T00:00:00Z` through `2026-10-15T21:30:00Z`. It selects all pull-request branches and pushes to main, enumerates every attempt, then requests the attempt's jobs and each keystroke job's logs. The collection completed on 2026-10-15. Jobs that started after the window are excluded. An in-progress job has no measurements in this snapshot. Recollection can discover later completions or later attempts, so its counts can change.

All 86 available independent logs identify the same hosted `macos-15-arm64/20260907.0337` image. The noise labels report three cores. Each run uses its locked dependencies and a mock production build in WebKit. Tracing is off for measured typing, palette, and scrolling.

One row identifies a run, attempt, branch, head SHA, checkout SHA, and job result. Typing measurements form a map keyed by surface. Missing values stay missing, so cancelled setup and older recorders cannot masquerade as zero latency. PR jobs check out a merge commit. Repeated-checkout comparisons below hold that exact commit constant as well as the head.

GitHub can carry a successful job into a later attempt with a new job ID but its original start time and logs. Nine rows have the same run and start time as an earlier attempt. The analysis retains those rows in the audit table and counts their measurements once. Four distinct checkouts have genuine repeated palette and scroll measurements.

The earliest logged load is `t+0s load1` at entry to the quiet-machine wait, after the mock build. This is the available job-start proxy, not a load sampled at VM provisioning. The table also keeps wait-exit load and the load printed with each palette and scroll result. Typing end loads remain in the collector's local JSON output.

## Reproduce the extraction

Run these commands from the repository root with authenticated `gh`, Node, and Python 3:

```sh
node scripts/collect-keystroke-ci.mjs 2026-10-13T00:00:00Z 2026-10-15T21:30:00Z /tmp/keystroke-ci.json
python3 docs/evidence/hosted-keystroke-calibration/summarize.py.txt /tmp/keystroke-ci.json
```

The archived `collect-keystroke-ci.mjs.txt` is the exact collector used for this record. It calls `repos/aelomi/aelomi/actions/runs/<id>/attempts/<n>/jobs` and `repos/aelomi/aelomi/actions/jobs/<id>/logs`. JSON output stays local. No raw logs, traces, screenshots, or hash manifests are committed.

The summarizer checks every extracted palette result has 55 keys, every typing summary has 405 retained samples from three loads, and every scroll result has more than 200 frames. The tests also assert exact character updates, scroller movement, and end stamps. The retained sample and frame counts show that the timed work ran. A printed summary can precede a later assertion failure, so failed jobs remain labelled and contribute their observed latency rather than a fabricated pass. Earlier runs without compatible summaries stay missing.

## Selection and interpretation

The claim tested here is that the former hosted palette and scroll ceilings change verdict on identical code. It is not a claim that one PR makes the app faster or slower.

Use `ceil(1.5 * worst observed)` in whole milliseconds, the existing cold-start method. All main and PR observations count, including failures. Do not discard noisy results to make a budget pass.

- Palette p95 spans 25 to 58 ms. `ceil(1.5 * 58)` gives **87 ms**, replacing 40 ms.
- Longest scroll interval spans 20 to 55 ms. `ceil(1.5 * 55)` gives **83 ms**, in a separate hosted entry. Local remains 50 ms.
- Keep the single-interval maximum. A bounded allowance for over-50 ms frames would require a new recorder statistic. Existing logs report only the maximum and, in newer jobs, over-33 ms counts. They cannot establish an exact over-50 ms allowance. A hosted maximum preserves a hard limit on severe stalls with the same calibration rule.

The five main measurements overlap the PR distributions. Main palette p95 is 25 to 33 ms, compared with PR values of 25 to 58 ms. Main scroll work p95 is 12 to 23 ms, compared with 9 to 23 ms on PRs. Main longest interval is 22 to 44 ms, compared with 20 to 55 ms on PRs. The PR tails alone do not identify a code regression.

For the unchanged `838f056` head and `ce40245` checkout, three jobs give these relevant excerpts:

```text
palette p95 29 ms; scroll rendering p95 20 ms; longest interval 51 ms
palette p95 58 ms; scroll rendering p95 17 ms; longest interval 28 ms
palette p95 25 ms; scroll rendering p95 15 ms; longest interval 55 ms
```

The first and third jobs fail the old scroll ceiling. The second fails the old palette ceiling. All six metric values fit the proposed ceilings. The 55 ms interval reports `previous frame's work 2 ms, then 53 ms to the next stamp`. That interval's tail lies outside the recorder's measured previous-frame work. Other jobs report negative between-frame values, so this decomposition is not a physical presentation trace.

The load table reports ordinary squared Pearson correlation, equivalent to a one-predictor linear model with an intercept. The within-checkout column first subtracts each checkout's mean load and mean latency. The variation share is `sum((value - checkout mean)^2) / sum((value - overall mean)^2)` over only genuinely repeated checkouts. Missing values are excluded per metric. Each job has equal weight. Four groups and ten jobs are a small repeated sample.

Wait-entry load accounts for only 1.4% of palette variance, 0.0% of scroll-work variance after rounding, and 2.0% of longest-interval variance in these linear associations. In the repeated subset, 90.5%, 56.4%, and 56.5% of variance respectively occurs without changing the checkout. Checkout-centered load associations account for 16.4%, 3.0%, and 0.1% of that within-checkout variance. The typing rows apply the same calculation separately to every surface.

These are associations, not percentages caused by load or code. Between-checkout variance includes host state, test-version changes, and code. Start load is stale by the later tests, and no CI CPU or I/O profile isolates a limiting resource. A causal split between load, scheduler delay, and code is **inconclusive**. The repeated-checkout spread does establish that code differences cannot explain all variation. No paired, alternating benchmark of main against each PR was run, so this record makes no PR-versus-main speed claim.

The two-minute wait often lowers load but no complete logged wait reaches 2.5. The logs contain no measurements after an extra three-minute wait. Retain the 120-second wait instead of assuming that 300 seconds fixes late-test noise. The workflow and `check-all-stages.ts` commands and environments are unchanged.

The local palette ceiling stays 16 ms. Local scroll work stays strictly below 16.7 ms and its maximum stays 50 ms. Local typing stays at the accepted 19 ms, with the 16 ms SPEC goal recorded. Search, cold start, storage, backlinks, all sample counts, and all correctness guards are unchanged.

One older repeated checkout, `c4d2a7f`, reports large-editor app-owned p95 of 35, 56, and 32 ms. The 56 ms observation exceeds the existing 45 ms hosted typing gate. This task recalibrates palette and scroll only. The typing calibration remains a known gap rather than silently expanding a third gate. Synthetic typing surfaces remain diagnostic.
