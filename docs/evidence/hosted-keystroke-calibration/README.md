## Environment and data shape

The collector reads every `CI` workflow run created from `2026-10-13T00:00:00Z` through `2026-10-15T21:30:00Z`. It selects all pull-request branches and pushes to main, enumerates every attempt, then requests each keystroke job's logs. Jobs that started after the window are excluded using parsed timestamps. Recollection on 2026-10-15 includes a fourth `838f056` attempt that was unfinished in the first snapshot. The sample grows from 39 to 40 palette and scroll observations, and from 43 to 44 large-editor typing observations.

All 87 available independent logs identify hosted image `macos-15-arm64/20260907.0337`. The noise labels report three cores. Each job uses its locked dependencies and a mock production build in WebKit. Tracing is off for measured typing, palette, and scrolling.

One row identifies a run, attempt, branch, head SHA, checkout SHA, job result, and measurements. Typing measurements form a map keyed by surface. The collector marks carried jobs with `carriedFrom`, using a map keyed by run ID and parsed job-start time. Consumers filter that field rather than rediscovering duplicates. The table retains all nine carried rows and counts their measurements once.

An absent test leaves its metrics absent. A test title without a parseable summary adds a named `summaryErrors` entry, prints the run, attempt, job, and surface to stderr, and makes the collector exit nonzero. Valid measurements from that job remain available. [Job 116152805524](https://github.com/aelomi/aelomi/actions/runs/38650502888/job/116152805524) has one genuine missing summary. Its large-editor fixture failed before measurement:

```text
Error: expect(locator).toBeVisible() failed
Locator: getByTestId('page-editor')
Timeout: 5000ms
```

That surface supplies no timing value. The other surfaces, palette, and scroll in its log remain measured. The collector reports this error instead of emitting a null timing for the titled test. Older scroll recorders lack the over-33 ms counter; their counter stays missing.

PR jobs check out a merge commit. Repeated-checkout comparisons hold that exact commit constant as well as the head. The earliest load is `t+0s load1` at entry to the quiet-machine wait, after the mock build. This is the available job-start proxy. The table also retains wait-exit load and the load printed with each palette and scroll result.

## Reproduce the extraction

Run these commands from the repository root with authenticated `gh`, Node, and Python 3:

```sh
node scripts/collect-keystroke-ci.mjs 2026-10-13T00:00:00Z 2026-10-15T21:30:00Z /tmp/keystroke-ci.json
python3 docs/evidence/hosted-keystroke-calibration/summarize.py.txt /tmp/keystroke-ci.json
```

The first command exits 1 for the missing-summary error described above and still writes the extracted observations. Inspect every reported error before using the second command. The archived `collect-keystroke-ci.mjs.txt` is the collector used for this record. It calls `repos/aelomi/aelomi/actions/runs/<id>/attempts/<n>/jobs` and `repos/aelomi/aelomi/actions/jobs/<id>/logs`. JSON output and raw logs stay local.

The summarizer validates retained counts before printing. Every palette result has 55 keys, every typing result has 405 samples, and every scroll result has more than 200 frames. The specs also assert exact character updates, scroller movement, and end stamps. A printed summary can precede a later assertion failure, so failed jobs retain their actual conclusion and measured values.

## Selection and interpretation

Use `ceil(1.5 * worst observed)` in whole milliseconds for palette p50 and scroll work p95, with p95 and longest-interval backstops by the same rule. This uses the brief's multiplier on each job's statistic. Cold start applies that multiplier to a series median, so the two calibrations do not have identical sampling semantics. All main and PR observations count, including failures and noisy jobs.

Palette p50 has a 33 ms ceiling and scroll rendering-work p95 has a 35 ms ceiling. The generated sensitivity table below gives the smallest regression each gate catches on the median runner. The p50 gate cannot see changes confined to a few keys. Palette p95 remains at 87 ms as a backstop. Hosted scroll changes from the original 50 ms longest interval to an 83 ms backstop, alongside the new work-p95 gate. Local palette stays at 16 ms p95; local scroll stays strictly below 16.7 ms work p95 with a 50 ms interval maximum. Typing stays at 19 ms locally, with the 16 ms SPEC goal recorded.

The scroll maximum bounds spacing between rAF timestamps. It does not bound every work stall or compositor presentation. [Job 116673405096](https://github.com/aelomi/aelomi/actions/runs/38804288552/job/116673405096) reports:

```text
scroll frames 294, rendering work p50 2 ms p95 15 ms (budget < 16.7) max 115 ms, longest interval 55 ms (budget 50)
```

Its 115 ms work maximum and 55 ms interval would pass these hosted gates. WebKit can backdate rAF timestamps; another job measured 74 ms of work with a 35 ms longest interval. Work max remains information. The over-33 ms count is retained in the table but exists for only 31 jobs. No existing counter gives an exact over-50 ms allowance. Keep the interval maximum as a timestamp-spacing backstop, with work p95 as the steady gate. Issues #72 and #87 retain the timing and calibration gaps.

For unchanged `838f056` and checkout `ce40245`, the four attempts report these summaries:

```text
palette p50 18 ms p95 29 ms; scroll work p95 20 ms; longest interval 51 ms
palette p50 20 ms p95 58 ms; scroll work p95 17 ms; longest interval 28 ms
palette p50 15 ms p95 25 ms; scroll work p95 15 ms; longest interval 55 ms
palette p50 12 ms p95 31 ms; scroll work p95 13 ms; longest interval 35 ms
```

The first and third jobs exceed the old scroll ceiling. The second exceeds the old palette ceiling. All four fit the new gates. This is unexplained hosted run-to-run variance. Main and PR ranges overlap. No CI CPU or I/O profile isolates a limiting resource, so a causal split between load, scheduler delay, and code is inconclusive.

The generated load table reports signed Pearson correlation and its square, both against wait-entry load and against each result's load. The centered column subtracts each checkout's mean load and mean latency. Within-checkout variation is `sum((value - checkout mean)^2) / sum((value - overall mean)^2)` over the repeated subset. Missing values are excluded per metric. Each job has equal weight. All four repeated palette and scroll checkout groups are reruns after a failed first attempt, which selects for noisy groups. Their 11 measured jobs are a small, selected sample. Typing has additional earlier measurements; the table calculates each surface separately. Neither the correlations nor the variance shares identify how much spread load or code caused. No paired, alternating comparison of main and each PR was run.

No complete logged quiet wait reaches load 2.5. The logs contain no observations after an extra three-minute wait. Retain the 120-second wait because the data does not establish that 300 seconds helps. CI commands and effective environments are unchanged.

Keep the hosted typing gate at 45 ms. The first snapshot had one exceedance in 43 large-editor observations; recollection has one in 44, about 2.3%. Unchanged checkout `c4d2a7f` measured 35, 56, and 32 ms. [Job 116394063809](https://github.com/aelomi/aelomi/actions/runs/38725304063/job/116394063809) measured the 56 ms exceedance. [PR #86](https://github.com/aelomi/aelomi/pull/86) separately reported 47 ms outside this window. Raising typing by the same rule would give 84 ms and weaken its regression sensitivity. At its 34 ms median, 45 ms fails above an added 11 ms; the first whole-ms failure is 46 ms, +12 ms or 1.35x. This remains a known false-failure risk for a typing-specific fix in #87.
